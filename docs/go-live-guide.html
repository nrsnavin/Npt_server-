1Before you start

How to read the commands

  • Grey-on-dark boxes are commands. Copy them one box at a time and press Enter.
  • If a box starts with cd, the folder matters. If not, the command works from anywhere.
  • In nano (the text editor): save with Ctrl O, then Enter; exit with Ctrl X.
  • Lines starting with # are comments; they do nothing if pasted.

Three ways to host it

A. One EC2 server this guide

API, web app and MongoDB on one box. Cheapest and simplest. You own patching and backups (Part 9 sets those up).

Cost: about $24/month.

B. EC2 + MongoDB Atlas

The database moves to MongoDB's managed service in Mumbai (ap-south-1), with its own backups and a replica set built in. Skip the MongoDB steps in Part 5 and follow Part 5B instead. Choose this when losing a day of data is not acceptable.

Cost: EC2 as above, plus Atlas: Flex about $8–30/month, a dedicated M10 about $57/month.

C. Amazon Lightsail

The same Ubuntu server as a fixed bundle: the 2 GB plan (about $12/month) and 4 GB plan (about $24/month) include the IP address, disk and data transfer. Every command in this guide works; only the console screens differ (Networking tab for the firewall and a static IP). Simpler billing, fewer AWS features later.

Recommendation: Option A on t3.small (or t4g.small), 40 GB gp3, in Mumbai. Move to t3.medium when more than 25 people use it at the same time.

3.3 Security group (the firewall)

TypePortSourceWhy
SSH22My IPNever 0.0.0.0/0: an open SSH port is attacked within minutes. Update it if your office IP changes.
HTTP80Anywhere (0.0.0.0/0)Needed for the HTTPS certificate; then redirects to HTTPS
HTTPS443Anywhere (0.0.0.0/0)The app and the WhatsApp webhook
Do not open port 27017 (MongoDB) or 5000 (the API). Both stay private to the server; Nginx is the only way in from outside.

3.4 Fixed IP address (Elastic IP)

  1. EC2 → Network & Security → Elastic IPs → Allocate Elastic IP address → Allocate.
  2. Select it → Actions → Associate Elastic IP address → choose the npt-erp instance → Associate.
  3. Write the address on your sheet as <ELASTIC_IP>. Without it, the IP changes on every stop/start and your domain points at nothing.

3.5 Already running on a t2.micro? Resize it

No reinstall is needed. Data, disk and Elastic IP stay as they are. Expect about 5 minutes of downtime, so do it outside working hours.

  1. Take a backup first: EC2 → Volumes → select the volume → Actions → Create snapshot.
  2. EC2 → Instances → select it → Instance state → Stop instance. Wait for Stopped.
  3. Actions → Instance settings → Change instance type → t3.small → Apply.
  4. Instance state → Start instance. Then on the server: pm2 status should show npt-api online.

Ubuntu 22.04/24.04 images already have the drivers a t3 needs. Moving x86 → ARM (t4g) is not a resize; that needs a new instance.

3.6 Connect over SSH

# Mac / Linux / Windows PowerShell — run from the folder holding the key
chmod 400 npt-erp.pem            # Mac/Linux only
ssh -i npt-erp.pem ubuntu@<ELASTIC_IP>

Answer yes to the fingerprint question the first time. You are in when the prompt reads ubuntu@ip-…:~$.

4.1 Add two A records at your DNS provider

Hostinger: Domains → your domain → DNS / Nameservers → DNS records. GoDaddy: My Products → Domain → DNS → Add New Record. Others: look for "DNS management" or "Zone editor".

TypeName / HostPoints to / ValueTTL
Acrm<ELASTIC_IP>300 (or the lowest offered)

  • Type only crm in the Name box, not crm.navinplastic.com; the panel adds the domain itself.
  • If a crm or api record already exists (A or CNAME), edit it instead of adding a second one.
  • Leave MX, TXT, SPF and DKIM records alone. They carry your company email. Adding subdomains does not affect email; deleting the wrong row does.

Only if you want AWS to hold the DNS (about $0.50/month): Route 53 → Hosted zones → Create hosted zone for navinplastic.com, copy every existing record (especially MX and TXT for email) into it, add the two A records above, then replace the nameservers at your registrar with the four Route 53 shows. Copy the email records first, or company email stops. If unsure, stay with 4.1.

5.5 Create the database admin

Make up a long password with letters and digits only (symbols like @ : / break the connection string). Write it on your sheet.

mongosh --eval 'db.getSiblingDB("admin").createUser({ user: "nptadmin", pwd: "PUT-YOUR-LONG-PASSWORD", roles: [{ role: "root", db: "admin" }] })'

5.6 Turn on passwords and transactions

The app saves related records together (an order and its number, a customer and its first enquiry). MongoDB does that only as a replica set, so this makes the single server a one-node replica set. Same data, same port.

openssl rand -base64 756 | sudo tee /etc/mongod-keyfile >/dev/null
sudo chown mongodb:mongodb /etc/mongod-keyfile
sudo chmod 400 /etc/mongod-keyfile
sudo nano /etc/mongod.conf

Find the line #security: and replace it (and any #replication: line) with these lines, keeping the two-space indents:

security:
  authorization: enabled
  keyFile: /etc/mongod-keyfile
replication:
  replSetName: rs0
sudo systemctl restart mongod
mongosh -u nptadmin -p --authenticationDatabase admin \
  --eval 'rs.initiate({ _id: "rs0", members: [{ _id: 0, host: "127.0.0.1:27017" }] })'
# It asks for the password; the answer should include  ok: 1

5.7 Redis (only with two API processes, on t3.medium)

sudo apt install -y redis-server
sudo systemctl enable --now redis-server
redis-cli ping      # PONG

5B.1 Create the cluster

  1. Sign up at cloud.mongodb.com with the company email. Create an organisation Navin Plastic Tech and a project NPT CRM.
  2. Create cluster → choose Flex → provider AWS → region Mumbai (ap-south-1), the same region as the server. Name it npt. Create.

5B.2 A database user

  1. Security → Database Access → Add new database user.
  2. Authentication: Password. Username nptapp. Click Autogenerate secure password and copy it to your sheet.
  3. Role: Read and write to any database. Add user.

5B.3 Let only your server in

  1. Security → Network Access → Add IP address.
  2. Enter your <ELASTIC_IP> with a comment npt-erp server. Confirm.
Never add 0.0.0.0/0 ("allow from anywhere"). With only the server's IP listed, nobody else can even try the password. If you rebuild the server with a new IP, add the new one here and remove the old.

5B.4 The connection string

  1. On the cluster, Connect → Drivers → Node.js. Copy the string; it looks like mongodb+srv://nptapp:<password>@npt.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=npt
  2. Replace <password> with the generated one, and put the database name npt_erp after .net/.
  3. In the server's .env (Part 6.2), use it as MONGO_URI:
MONGO_URI=mongodb+srv://nptapp:THE-GENERATED-PASSWORD@npt.xxxxx.mongodb.net/npt_erp?retryWrites=true&w=majority&appName=npt

No replicaSet= part is needed: Atlas is already a replica set, so transactions work. Check after Part 8 that /health/ready shows "transactions": true.

5B.5 Moving data you already have

Only if a database is already running on a server (for example the current t2.micro). Install the tools, copy, then switch:

sudo apt install -y mongodb-database-tools    # on the old server, if mongodump is missing
mongodump --uri="mongodb://nptadmin:OLD-PASSWORD@127.0.0.1:27017/npt_erp?authSource=admin" --archive=npt.archive --gzip
mongorestore --uri="mongodb+srv://nptapp:THE-GENERATED-PASSWORD@npt.xxxxx.mongodb.net" --archive=npt.archive --gzip --nsInclude='npt_erp.*'
# then set MONGO_URI to the Atlas string in .env and:
pm2 reload npt-api --update-env

Do it outside working hours: anything saved between the dump and the switch would be left behind on the old database. The old server's own Network Access entry (its IP) must be added in 5B.3 for the restore to connect.

5B.6 What changes elsewhere in this guide

  • Part 9 backups: remove the two mongodump lines from backup.sh; Atlas backs the database up. Keep the S3 sync of uploads/ — the photos and PDFs are still on the server.
  • Part 9.3 restore: done from the Atlas screen (Cluster → Backup → Restore), not with mongorestore.
  • Server size: without MongoDB on it, a t3.small has room for two API processes; Redis (5.7) is then recommended.
  • Monitoring: Atlas emails you on high load or a full disk; set your email under Project → Alerts.

7Nginx and HTTPS certificates

7.1 Security headers (one shared snippet)

sudo nano /etc/nginx/snippets/npt-security.conf

7.2 The two sites

sudo nano /etc/nginx/sites-available/npt
# The web app
server {
    listen 80;
    server_name crm.navinplastic.com;
    root /srv/npt/web/dist;
    index index.html;
    include snippets/npt-security.conf;

    location / { try_files $uri $uri/ /index.html; }      # reload on any screen works
    location = /index.html {
        add_header Cache-Control "no-cache";
        include snippets/npt-security.conf;
    }
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        include snippets/npt-security.conf;
        try_files $uri @previous;                          # tabs open across a deploy
    }
    location @previous {
        root /srv/npt/web/dist.old;
        expires 1y;
        add_header Cache-Control "public, immutable";
        include snippets/npt-security.conf;
    }
    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
}

# The API (and the WhatsApp webhook)
server {
    listen 80;
    server_name api.navinplastic.com;
    client_max_body_size 25M;                              # phone photos and PDFs

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}
sudo ln -s /etc/nginx/sites-available/npt /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx      # must say "syntax is ok"

7.3 Free HTTPS certificates (Let's Encrypt)

Only after Part 4.3 shows both names pointing at your Elastic IP:

sudo snap install --classic certbot
sudo ln -sf /snap/bin/certbot /usr/bin/certbot
sudo certbot --nginx -d crm.navinplastic.com -d api.navinplastic.com
sudo certbot renew --dry-run       # proves automatic renewal works

Give an email for expiry notices, agree to the terms, and choose redirect if asked. Certificates renew by themselves every 60–90 days.

After HTTPS works for a week, you may add add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always; to the snippet. Browsers then refuse plain http for a year, so add it only once HTTPS is solid.

9Backups and the disk alarm

The database and the uploaded files cannot be rebuilt from git. A backup on the same disk is not a backup, so both go to S3 every night.

9.1 An S3 bucket and a backup user

  1. S3 → Create bucket: name npt-erp-backups-<something unique>, region Mumbai, Block all public access on, Bucket versioning: Enable.
  2. IAM → Users → Create user npt-backup → attach a policy allowing s3:PutObject, s3:GetObject, s3:ListBucket on that bucket only → Security credentials → Create access key (type "Command Line Interface").
  3. Optional saving: in the bucket, add a lifecycle rule moving uploads/ to Standard-IA after 30 days and expiring old versions after 90.
sudo snap install aws-cli --classic
aws configure          # paste the key and secret; region ap-south-1; output json

9.2 The nightly script

mkdir -p /srv/npt/backups
nano /srv/npt/backup.sh
#!/bin/bash
set -euo pipefail
STAMP=$(date +%F-%H%M)
OUT=/srv/npt/backups
BUCKET=s3://npt-erp-backups-YOURNAME
mongodump --uri="mongodb://nptadmin:PUT-YOUR-LONG-PASSWORD@127.0.0.1:27017/npt_erp?authSource=admin" \
  --archive="$OUT/npt-$STAMP.archive" --gzip
find "$OUT" -type f -name '*.archive' -mtime +14 -delete      # keep 14 nights on the box
aws s3 sync "$OUT" "$BUCKET/db/" --exclude '*.log'
aws s3 sync /srv/npt/server/uploads "$BUCKET/uploads/"
chmod 700 /srv/npt/backup.sh
/srv/npt/backup.sh             # run once now; check the files appear in S3
crontab -e                     # add the line below: every night at 2 am
0 2 * * * /srv/npt/backup.sh >> /srv/npt/backups/backup.log 2>&1

The server clock is UTC: 2 am UTC is 7:30 am in India. Use 30 20 * * * for 2 am India time.

9.3 Restore (test this once before you need it)

mongorestore --uri="mongodb://nptadmin:PUT-YOUR-LONG-PASSWORD@127.0.0.1:27017/?authSource=admin" \
  --archive=/srv/npt/backups/npt-2026-10-13-0200.archive --gzip --drop

9.4 Disk alarm

A full disk stops MongoDB and the whole app. Simplest check: df -h / every week, and grow the disk at 75% (EC2 → Volumes → Modify, then sudo growpart /dev/nvme0n1 1 && sudo resize2fs /dev/nvme0n1p1, no downtime). For an automatic email, install the CloudWatch agent with the disk used_percent metric and create an alarm at 75%.

Also: EC2 → Elastic Block Store → Lifecycle Manager can snapshot the whole disk every night (a few dollars a month) as a second layer.

10Deploying updates

When new work is merged to main, put it on the server with one script.

nano /srv/npt/deploy.sh
#!/bin/bash
set -euo pipefail
echo "→ API"
cd /srv/npt/server
git pull origin main
npm ci --omit=dev
pm2 reload npt-api --update-env       # new process starts before the old stops

echo "→ Web"
cd /srv/npt/web
git pull origin main
npm ci
rm -rf dist.old && cp -r dist dist.old   # keep the previous build for open tabs
npm run build
echo "✓ deployed"
chmod +x /srv/npt/deploy.sh
/srv/npt/deploy.sh
curl -s https://api.navinplastic.com/health/ready
  • Deploy outside busy hours when you can. A reload drops no requests, but a bad release affects everyone.
  • Staff do not need to do anything; open screens pick up the new version on their next page change.
  • Data scripts (migrations) never run by themselves. When a release note asks for one: take a backup (Part 9), run it once without --confirm to see what it would change, then with --confirm.
  • Roll back the web app: cd /srv/npt/web && mv dist dist.bad && mv dist.old dist. Roll back the API: cd /srv/npt/server && git reset --hard <previous commit> && npm ci --omit=dev && pm2 reload npt-api.
Automatic deploys (later). A GitHub self-hosted runner on the box can run deploy/on-box.sh after each merge, with a health check and automatic rollback. The full steps are in docs/DEPLOY-AWS.md §11 in the server repository. Start with the manual script; add the runner once things are stable.

11WhatsApp: Meta account and number

The app talks to WhatsApp through Meta's WhatsApp Cloud API directly, with no middleman. Once set up it:

  • sends quotations, LR copies, sample updates and trip notices to buyers, with the PDF;
  • sends department-task notices to staff on their own numbers;
  • receives buyer replies and photos into the WhatsApp inbox, and staff screenshots into Draft enquiries;
  • can send sign-in codes to people who sign in with a phone number.

Until it is set up, the app still works; messages it would have sent are written to the server log instead.

Do Parts 3–8 first. Meta needs the API live on HTTPS (Part 7) before the webhook in Part 12 can be verified. You can start Meta's business verification (step 2 below) on day one, because that is the slow part.

Meta renames its screens often. Look for the words in quotes rather than an exact path.

  1. Business portfolio. Open business.facebook.com, create or choose the portfolio Navin Plastic Tech. Fill in the legal name, address and website exactly as on the GST certificate.
  2. Business verification. Settings → "Security centre" → "Start verification". Upload the GST certificate or Udyam registration. Meta usually answers in 1–2 working days.
  3. Create the app. developers.facebook.com → "My Apps" → "Create app" → type "Business" → name NPT CRM → link it to the Navin Plastic Tech portfolio.
  4. Add WhatsApp. On the app dashboard, WhatsApp → "Set up". Meta creates a WhatsApp Business Account and a free test number.
  5. Add your real number. WhatsApp → "API Setup" → "Add phone number": display name Navin Plastic Tech, category Manufacturing, then confirm the number with the code Meta sends by SMS or call.
    The number must not be on the WhatsApp or WhatsApp Business app. If it is, delete the account in that app first (Settings → Account → Delete account) and wait a few minutes.
  6. Display name. Meta reviews it, usually within a day. Until then, messages show the number instead of the name.
  7. Billing. WhatsApp Manager (business.facebook.com/wa/manage) → "Payment settings" → add a card. Without it, only replies inside a buyer's 24-hour window go out.

14WhatsApp: screenshots to draft enquiries

A salesperson or admin forwards a buyer's chat screenshot or visiting card to the business number. The app reads it into a draft enquiry and replies with what it read. Nothing becomes a customer until a person checks and confirms it.

Turn it on

  1. Get an API key at console.anthropic.com (Settings → API keys) and add it to .env: 
    ANTHROPIC_API_KEY=sk-ant-...
  2. Put each salesperson's and admin's WhatsApp number on their user profile: Masters & Access → Users → the person → Phone. This is how the app knows a photo is from staff. A photo from any other number is treated as a buyer's message and goes to the inbox.
  3. pm2 reload npt-api --update-env.

How staff use it

  1. Screenshot the buyer's chat so the name or number at the top shows, or photograph their visiting card.
  2. Send it to the business number, up to 3 photos in one message. A caption is optional and is read too.
  3. Within about a minute, the app replies with what it read (company, name, mobile, email, place, product, quantity) and a link to the draft.
  4. Open the link (or Enquiries → Draft enquiries), correct anything wrong, and fill in the next step, follow-up date and how you met them. An admin can choose the salesperson in the Marketing person field.
  5. Click Confirm: the customer and first enquiry are created.
  • Long chats: send the screenshot with the buyer's name first; ones sent within 10 minutes join the same draft.
  • Existing buyers: if the phone or email already belongs to a customer, the reply says so and Confirm is refused; raise the enquiry on that customer.
  • No key or blurred photo: the draft is still saved, with the reason, for typing in by hand.
  • Without WhatsApp: the same reading works by uploading the photo on the Draft enquiries screen.

AGo-live checklist

Server

  • t3.small (or larger) in Mumbai, 40 GB gp3, Elastic IP attached
  • Security group: SSH from your IP only; 80 and 443 open; 27017 and 5000 closed
  • Swap on (free -m), firewall on (sudo ufw status)
  • MongoDB with a password and replica set: health shows "transactions": true
  • .env filled, chmod 600, not in git; OTP_EXPOSE_IN_RESPONSE=false
  • pm2 running and saved; pm2 startup line run (survives a reboot: test with sudo reboot)

Domain

  • A records for crm and api point at the Elastic IP; email records untouched
  • HTTPS padlock on both names; certbot renew --dry-run succeeded
  • CORS_ORIGIN, APP_URL, PUBLIC_API_URL, VITE_API_URL and the Nginx CSP all use the same names

Data safety

  • Nightly backup to S3 runs (check the bucket the next morning); versioning on
  • A restore was tried once on purpose
  • Weekly df -h / or a CloudWatch disk alarm at 75%

WhatsApp

  • Business verified; display name approved; billing card added
  • Permanent System User token; health shows "whatsapp": "meta"
  • Webhook verified, messages subscribed, app Live
  • Quote, LR copy and Task templates approved and set
  • Staff numbers on their user profiles; WhatsApp inbox access granted
  • All ten tests in Part 15 pass

People

  • Admin account created; staff added with departments
  • Staff told the address: https://crm.navinplastic.com (on phones: browser menu → "Install app" / "Add to Home screen")
